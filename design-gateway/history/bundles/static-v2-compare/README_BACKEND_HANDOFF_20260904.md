## 10. Data Ownership / Admin Operations
프론트엔드가 데이터를 영구 저장하는 구조로 구현하지 않습니다. 역할을 분리합니다.

- Frontend: 입력 폼, 화면 표시, 클라이언트 검증, API 호출
- Backend/API: 인증·권한 확인, 서버 검증, DB 저장/조회/수정/삭제
- Database/Object Storage: 게시글·공지·후기·문의·가게 정보·이미지 원본/URL 보관
- Admin/Operator: 단지온공지, 홈 대표 이웃가게 4곳, 신고·제보 승인, 이웃가게 등록/수정 등을 운영

### Required write flows
- 이웃가게 신청/제보: `POST /api/shop-applications` 계열
- 이웃가게 후기: `POST /api/shops/:shopId/reviews`
- 이웃가게 1:1 문의: `POST /api/shops/:shopId/inquiries` 또는 메시지 스레드 생성 API
- 주민소식 제보: `POST /api/resident-news-submissions`
- 일반 1:1 문의: `POST /api/support/inquiries`
- 댓글/답글/공감/저장: 각각 인증 사용자 기준 API

프론트의 현재 localStorage/sessionStorage 시연 데이터는 실제 API 연결 시 제거 또는 개발모드 전용으로 격리합니다.

## 11. Search

- `GET /api/shops?q=&category=&page=&pageSize=`
- `GET /api/notices?q=&kind=&page=&pageSize=`

## 12. Operator/Admin Requirement
오픈 후 공지나 가게 정보를 수정할 때 HTML을 직접 편집하지 않도록 **관리자 전용 운영화면 또는 최소 관리자 API**를 둡니다.

필수 운영 기능:
1. 단지온공지 작성/수정/게시/비공개
2. 아파트소식 작성/수정
3. 주민소식 제보 검토 후 승인/게시
4. 이웃가게 신청·제보 승인/반려/수정
5. 홈 대표 이웃가게 4곳 선택 및 노출 순서 변경
6. 가게 사진·소개·운영시간·혜택·카테고리 관리
7. 신고 콘텐츠/주민 차단 관련 운영 처리

초기 데이터 입력은 관리자 화면이 완성되기 전까지 seed/import로 넣을 수 있지만, 지속 운영은 관리자 기능을 기준으로 합니다.
