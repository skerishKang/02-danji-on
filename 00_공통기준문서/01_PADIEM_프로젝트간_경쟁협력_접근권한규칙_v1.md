# PADIEM 프로젝트간 경쟁·협력·접근권한 규칙 v1

- 기준일: 2026-08-07
- 적용대상: PADIEM CORE 및 모든 산하 프로젝트의 설계팀장·디자인팀장
- 최종 권한자: 제품 오너

---

## 1. 목적

PADIEM은 여러 프로젝트를 동시에 운영한다. 각 팀이 서로의 모든 자료를 상시 공유하면 프로젝트의 독립성이 약해지고 디자인이 서로 닮아갈 수 있다. 반대로 완전히 단절시키면 좋은 기술과 구현방식을 반복해서 새로 만들게 된다.

따라서 PADIEM은 다음 모델을 사용한다.

> **기본은 독립, 결과는 경쟁, 필요한 순간에는 선택적으로 협력한다.**

---

## 2. 기본 접근원칙: Default Closed

각 팀의 기본 작업범위는 자기 프로젝트 폴더다.

- 설계팀장은 자기 프로젝트의 `00_공통기준문서`, `01_설계팀`을 관리한다.
- 디자인팀장은 자기 프로젝트의 `02_디자인팀`, 승인된 결과영역을 관리한다.
- 타 프로젝트의 설계문서·디자인문서·개발소스·HTML 결과물을 상시 탐색하지 않는다.
- 타 프로젝트 폴더를 보고 싶다는 이유만으로 임의 열람하지 않는다.

**프로젝트 간 접근권한은 제품 오너의 명시적 지시가 있을 때만 열린다.**

---

## 3. 항상 공개되는 공통영역

다음 두 영역은 전 프로젝트가 공통으로 볼 수 있다.

### 3.1 PADIEM HQ 공통기준

`[[지피티 작업]]/[0.파디엠]/00_공통기준문서`

목적:

- 회사 정체성 공유
- 조직도 공유
- 사실표현·보안·품질 기준 공유
- 프로젝트 간 경쟁·협력 규칙 공유

### 3.2 공통 벤치마킹 영상

`[[지피티 작업]]/[00.벤치마킹 영상]`

이 폴더는 특정 팀의 독점자료가 아니다.

모든 설계팀장·디자인팀장이 같은 영상을 보고 자기 프로젝트 관점에서 분석한다. 같은 영상을 보고도 서로 다른 제품해석과 디자인결과를 만들어내는 것을 권장한다.

---

## 4. 타 프로젝트 HTML 결과물 공개

HTML 결과물은 프로젝트 간 경쟁과 학습을 위해 **제품 오너가 필요할 때 선택적으로 공개**할 수 있다.

공개가 지시된 경우 다음 규칙을 적용한다.

1. 공개 범위는 지시된 프로젝트와 지시된 결과물로 한정한다.
2. 기본 권한은 읽기·실행·분석이다.
3. 원본 HTML, CSS, JS, 이미지, 실행영상, 검증자료를 임의 수정·삭제·이동·이름변경하지 않는다.
4. 차용할 부분과 차용하지 않을 부분을 명시적으로 구분한다.
5. 다른 프로젝트의 화면을 통째로 복제하지 않는다.
6. 차용한 기능·인터랙션은 자기 프로젝트의 사용자문제와 브랜드에 맞게 재설계한다.
7. 공개가 끝났다고 해서 타 프로젝트 전체 폴더에 대한 상시권한이 생기는 것은 아니다.

---

## 5. 소스코드 공유는 HTML 열람보다 더 엄격하게 관리한다

소스코드 공유는 제품 오너가 명시적으로 허용한 경우에만 한다.

예: **또다른우주 ↔ 아스테리브**처럼 동일한 책·서가·WebGL 프로그램이나 기반 코드를 쓰게 할 필요가 있는 경우.

### 소스 차용 규칙

1. 어느 프로젝트의 어느 버전에서 가져왔는지 기록한다.
2. 원본 프로젝트 폴더를 직접 수정하지 않는다.
3. 원칙적으로 자기 프로젝트 폴더로 복사·fork한 뒤 수정한다.
4. 공통 모듈로 승격할 필요가 있으면 제품 오너 승인 후 PADIEM HQ가 별도 공통자산으로 관리한다.
5. 프로젝트별 브랜드·데이터·문구·도메인 로직은 분리한다.
6. 공통엔진과 제품별 레이어를 구분한다.
7. 경로·asset·dependency를 무단 변경해 원본 프로젝트 실행을 깨뜨리지 않는다.

### 차용 기록 최소항목

```text
원본 프로젝트:
원본 결과/소스 버전:
차용 파일 또는 모듈:
차용 이유:
변경 내용:
현재 프로젝트에서 새로 추가한 기능:
원본과의 호환 필요 여부:
```

## 6. 경쟁 규칙

PADIEM은 팀간 경쟁을 의도적으로 활용한다.

### 설계팀장 경쟁

- 문제정의가 더 선명한가
- 핵심 사용자를 더 정확히 잡았는가
- 범위와 비범위를 잘 자르는가
- 데이터·객체·관계를 더 논리적으로 설계했는가
- 제품 오너의 경험과 실제 현장을 잘 반영했는가
- 디자인팀이 바로 실행할 수 있는 명세를 만드는가

### 디자인팀장 경쟁

- 같은 설계에서 더 강한 경험을 만드는가
- 벤치마크를 단순복제가 아닌 자기 제품 언어로 번역하는가
- 실제 HTML로 핵심 인터랙션을 구현하는가
- 시각적 차별성이 있는가
- 사용성과 기능성을 함께 만족시키는가
- 결과물이 다른 팀이 참고하고 싶을 정도로 완성도가 높은가

### 금지되는 경쟁

- 타팀 원본 수정
- 파일 삭제·이동·이름변경
- 의도적 정보은폐
- 승인되지 않은 소스 가져오기
- 다른 팀의 결과를 자기 팀 최초 성과처럼 기록하기

## 7. 협력 규칙

협력은 제품 오너가 목적을 지정했을 때 수행한다.

허용 가능한 협력 유형:

- HTML 비교리뷰
- 특정 인터랙션 차용
- 동일 벤치마크 영상 분석결과 비교
- 소스코드 또는 컴포넌트 재사용
- 공통 검색·RAG·온톨로지·파일뷰어·WebGL 엔진 공유
- 두 프로젝트를 잇는 데이터/기능 인터페이스 설계

협력 후에도 각 프로젝트의 최종 설계책임과 디자인책임은 해당 팀장에게 남는다.

## 9. PADIEM HQ의 역할

PADIEM HQ는 팀간 자료를 무제한 공유하는 중계소가 아니다.

본사는 다음을 한다.

- 어떤 결과를 비교할 가치가 있는지 판단
- 제품 오너에게 선택적 공유를 제안
- 승인된 공유범위를 문서화
- 공통화할 가치가 있는 코드·패턴을 식별
- 프로젝트간 중복개발을 줄임
- 동시에 제품의 브랜드·문제정체성이 섞이지 않도록 경계 설정

**최종 공유 여부와 범위는 제품 오너가 결정한다.**

---

## 10. 팀장에게 전달할 한 문장

> 당신의 팀은 다른 PADIEM 팀과 결과물의 품질로 경쟁하고, 제품 오너가 지정한 순간에는 서로의 HTML·기술·소스를 선택적으로 배우고 협력한다. 그러나 기본적으로는 자기 프로젝트 폴더만 관리하며, 타 프로젝트 자료는 허가 없이 열람·수정하지 않는다. 공통 벤치마킹 영상과 PADIEM HQ 공통기준만 전팀 상시공유 대상이다.
