# 단지온 V2 현재 운영 원칙 — 2026-08-09

## 현재 단계

단지온 V2는 이제 **내부 개발 티가 나는 테스트 화면을 만드는 단계가 아니라, 외부에 실제 서비스처럼 보여주면서 제품을 검증하는 단계**로 전환한다.

외부 공개·홍보·시연 화면은 완성된 서비스처럼 보여야 한다. 내부 안전장치와 테스트 도구는 계속 유지하되, 사용자에게 보이는 제품 화면과 분리한다.

## 1. 외부 화면 원칙

외부에 보여주는 V2 화면에서는 다음을 제품 문구로 사용하지 않는다.

- 테스트 / 테스트 서비스
- 데모 / DEMO
- Preview / PREVIEW ONLY
- 실제 테스트 DB / 합성 데이터
- 개발자용 상태값·환경명·내부 식별자
- 사용자에게 필요하지 않은 영어 오류문구

외부 화면의 카피, 가게명, 혜택, 설명, 등록 흐름은 **실제로 운영 중인 동네 서비스처럼 자연스럽게 작성**한다.

기술적으로 비운영 환경을 사용하더라도 그것은 내부 구현 문제이며, 외부 UI가 일부러 미완성·가짜처럼 보이게 만드는 이유가 되어서는 안 된다.

외부 시연 주소와 내부 검증 주소는 분리한다.

- 외부 시연·홍보: `https://v2-showcase.padiem-danjion-web-preview.pages.dev`
- 내부 권한 검증: `https://v2-demo.padiem-danjion-web-preview.pages.dev`

내부 권한표·역할 전환기·검증용 안내는 `v2-demo`에만 둔다. 외부 showcase에는 표시하지 않는다.

## 2. 현재 개발 순서

**실제 인증과 저장소를 동시에 시작하지 않는다.** 다음 순서를 고정한다.

1. 로그인 없이 역할을 전환하는 현재 인증·권한 검증을 끝까지 마무리한다.
2. 일반 방문자 / 미인증 주민 / 인증 입주민 / 운영자 각각의 허용·거부 동작을 실제 Preview API와 Neon child DB로 확인한다.
3. 등록 → 운영자 승인 → 공개 재노출까지 권한 경계가 맞는지 확인한다.
4. 인증 검증이 모두 안정된 뒤 실제 로그인/인증 연결을 시작한다.
5. 실제 인증이 안정된 뒤 파일 저장소 연결을 진행한다.
6. 실제 서비스 운영·Production 전환은 별도의 최종 승인 단계로 둔다.

즉 현재 우선순위는 **인증 동작 검증 완료 → 실제 인증 구현 → 저장소 구현**이다.

## 3. 인증 검증 기준

현재 로그인 없는 검증 모드는 실제 인증 구현 전에 제품 권한 구조를 확정하기 위한 단계다.

반드시 다음이 성립해야 한다.

- 일반 방문자는 공개 가게·서비스 탐색 가능
- 일반 방문자는 주민 전용 연락처·혜택·운영 기능 접근 불가
- 미인증 주민은 공개 탐색과 허용된 등록 흐름 사용 가능
- 미인증 주민은 인증이 필요한 주민 전용 기능 접근 불가
- 인증 입주민은 주민 전용 연락처·혜택·등록 기능 사용 가능
- 일반 입주민은 운영자 승인 기능 접근 불가
- 운영자는 신청 검토·승인 가능
- 승인 후 공개 목록에 다시 노출됨
- 권한 거부는 서버가 최종적으로 강제함

Preview 검증에는 비운영 Neon child와 합성 계정만 사용한다. 실제 주민 개인정보는 넣지 않는다.

## 4. 실제 인증 시작 조건

위 권한 검증이 끝난 뒤에만 실제 로그인 방식을 연결한다.

실제 로그인 도입 시에도 기존 권한 계약은 바꾸지 않고, 현재의 합성 역할 식별자를 실제 로그인 사용자 식별자로 교체하는 방식으로 진행하는 것을 기본 원칙으로 한다.

로그인을 붙였다는 이유로 MVP 첫 화면을 로그인 장벽으로 막지 않는다. 공개 탐색은 계속 바로 접근 가능하게 유지한다.

## 5. 저장소 시작 조건

파일 저장소는 인증 검증과 실제 인증 연결이 안정된 뒤 진행한다.

저장소 단계에서는 다음을 별도로 검증한다.

- 가게 대표 이미지 업로드·교체·취소
- 등록 취소 시 고아 파일 방지
- 주민 인증 증빙의 비공개 저장
- 운영자만 필요한 비공개 자료 조회
- 삭제/폐기 정책
- 실제 개인정보와 공개 이미지의 저장 경계

저장소를 붙이기 전에는 외부 시연 화면의 완성도를 낮추지 않는다. 필요한 이미지는 안전한 비운영 자산으로 구성한다.

## 6. 제품 표현 원칙

앞으로 V2를 만들 때 기본 판단 기준은 다음과 같다.

> 내부는 엄격하게 검증하되, 외부에는 실제 서비스처럼 보여준다.

안전성은 코드, 권한, 환경 분리, 데이터 분리, CI에서 확보한다. 사용자 화면에 `테스트`, `데모`, `Preview`라는 경고를 반복 노출하는 방식으로 안전성을 대신하지 않는다.

외부 시연 화면에 개발자용 문구가 다시 들어오는 것은 회귀로 취급하고 제거한다.

## 현재 상태

- V2 외부 showcase 분리: 완료
- 외부 화면의 테스트/Preview 표현 제거: 완료
- 로그인 없는 역할 전환 검증: 완료 및 회귀 테스트 유지
- 일반 방문자/미인증/인증 입주민/운영자 권한 경계: 검증 완료
- 신청 → 승인 → 공개 재노출 실제 Preview 흐름: 검증 완료
- 실제 로그인/인증 구현: 다음 단계, 아직 시작하지 않음
- 실제 저장소 연결: 인증 이후 단계
- Production 전환: 아직 아님

이 문서는 이후 단지온 V2 구현 시 현재 운영 기준으로 사용한다.
